# Scorer Updates and Versioning

Assessment rubrics often undergo iterative refinement between semesters or during initial marking calibration. Feedback Kitchen maintains an audit trail using configuration versioning and cryptographic rubric hashing.

### The versioning model

Each assessment scorer encapsulates two version dimensions:

- **Semantic Configuration Version:** A user-facing version string (e.g. `1.0`, `1.1`) configured in the Scorer Builder.
- **Deterministic Rubric Hash (`SA.rubricVersionHash`):** An 8-character hex hash computed directly over all criteria names, percentage weights, and tier descriptors.

Any change to a criterion title, percentage weight, or descriptor sentence automatically generates a new rubric hash.

### Editing an existing scorer

To update a saved assessment scorer:

1. Locate the scorer card on the home dashboard (`index.html`).
2. Click **Edit** to launch the **Builder Wizard** (`builder.html?id=<id>`).
3. Modify criteria, weights, descriptors, or grade scale settings.
4. Advance to Step 6 and click **Save & Start Scoring**.

The updated configuration replaces the previous version in `localStorage` (`SA_CONFIGS`).

### Per-record version stamping

When you mark and save a student, Feedback Kitchen stamps the active `rubricVersion` hash onto that student's record.

This ensures that:

- Previously marked students permanently retain the descriptors and weights active at the moment of evaluation.
- If an assessment is edited mid-marking, historical records are not silently retrofitted with new wording.
- The **Cohort Workbench** can instantly detect mixed-rubric cohorts and display the **Rubric drift detected** alert.

### Preserving audit trails in exports

Every export generated by Feedback Kitchen embeds version metadata:

| Export Target | Version Metadata Embedded | Purpose |
|---|---|---|
| **Single Marker Record (`.xlsx`)** | Scorer version, app version, date, and full rubric sheet. | Formal grade appeal documentation. |
| **Cohort Class Workbook (`.xlsx`)** | Full rubric descriptor reference sheet matching the cohort. | Institutional gradebook verification. |
| **Moderation Export (`.xlsx`)** | 8-character rubric hash, or `mixed` plus the list of versions, in the `90_manifest` sheet, with the schema version recorded in `00_README` and `20_methods`. | External examiner accreditation audit. |
| **Scorer Backup (`.json`)** | Full JSON schema including version strings and timestamps. | Team distribution and archival backups. |

### Best practices for marking teams

When a course coordinator updates a shared rubric:

1. Re-export the modified scorer as a `.json` file with **Export (Save / Share)** on Step 6 of the builder.
2. Distribute the new JSON file to all tutors with a clear instruction to re-import.
3. Tutors import the file via `upload.html`, updating their local rubric baseline while preserving their personal snippet libraries.
